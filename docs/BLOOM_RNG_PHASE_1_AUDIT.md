# Current Architecture

Rojo `default.project.json` maps `src` into DataModel and ignores unknown Workspace instances. Server boot: `ServerBootstrap.server.luau` removes named old client scripts and roulette GUI objects, requires DataService and PlayerService and 20 named services, runs ConfigValidation, calls Data:Init → Player:Start → Data:Start. Player:Start injects shared service context (`X`), runs every Init in the listed order, creates map and remotes, listens for profile load, then runs 0.5-second simulation ticks and one-second public bee/token broadcasts. The apparent service graph is a hub, not independent lifecycles: RemoteService → PlayerService:Request → Roll/Inventory/Garden/Workshop/Season/Trial/etc.; Roll → Inventory:Grant; Garden activity/pollination → Roll:Charge, mastery and social; Hive → Workshop points and garden capacity; Map → Trials/activities; UIStateService → Inventory/Workshop/Map/Trials snapshots.

Client boot: `ClientBootstrap.client.luau` requires `Controllers/BloomUI.luau`, whose Start resolves the authored PlayerGui/BloomUI and waits for SafeRoot, binds references, initializes RewardPresentation, Activity, Pollinator, TutorialGuide, GardenPresentation, subscribes to BloomRemotes/Event, and requests initial state via StateRequest. `InventoryV2Controller` is required by BloomUI. ReactPackages exists but is not referenced by this boot graph. Shared requires: configs supply Flowers/Bees/RollPool/Workshop/Locations; SeasonPlan and ProfileSchema supply migration/turn rules; `WorkshopEffectsConfig` is presentation metadata, while server services read node flags directly.

Remotes: RemoteService creates only `BloomRemotes/Request` (client→server event), `Event` (server→client event), and `StateRequest` (client→server function). PlayerService owns action routing, RemoteService owns transport/rate limits; ProximityPrompt handlers are server entry points with distance checks. All authoritative rewards, costs, unlocks, inventory and roll selection occur on the server. The client receives `State` with a copied profile, odds, derived UI state and other fields; each request returns Ack and a fresh full snapshot. StateRequest also produces a fresh full snapshot. No separate old FruitRNG remote is instantiated by this boot graph.

Profile lifecycle: `DataService` chooses `FruitRNG_PlayerProfiles_v1` in production and `FruitRNG_PlayerProfiles_TEST_v1` in Studio, key `Player_<userId>`. UpdateAsync acquires a 180-second token lease, wraps old raw records, runs ProfileSchema.Prepare, publishes loaded signal; PlayerService builds plot and HUD state. Autosave every 60–90 seconds uses a deep copy and UpdateAsync ownership check. PlayerRemoving and BindToClose call ReleaseProfile; SeasonConfirm uses a durable CommitProfile transaction and refuses to overwrite an unknown transaction outcome. SchemaVersion=5, BloomReworkV1 migration maps old fruit inventory and dust, archives ambiguous legacy currency, and removes old keys. The schema reconciles table shapes and checks serializability, but is not a strict per-field invariant validator.

Action flow: GUI Send(action,args) → RemoteService token bucket → PlayerService:Request → service-specific validation/mutation → Ack and full Push → BloomUI:ApplyState → Render and potentially RenderMenu. Proximity prompts invoke equivalent services directly and Push.

# P0 Issues

**BR-001 · P0 · Data safety.** Files: `src/ServerScriptService/Services/DataService.luau`, `src/ServerScriptService/Data/DataConfig.luau`. **Observed in code:** ReleaseProfile sets Closing, calls SaveProfile(true), then clears `recordsByUserId` even if every save attempt failed; Shutdown waits only 25 seconds, while retries plus concurrent releases can exceed that budget. A failed final save leaves a leased prior snapshot in the store and discards unsaved in-memory progression. **Root cause:** final-save failure has no recoverable handoff/retry persistence and record removal is unconditional. **Impact:** actual unsaved rewards/progression can be lost on departure or shutdown; no claim is made that this has already occurred. **Recommended fix:** retain failed closing records while the server is alive, retry with bounded backoff and explicit outcome logging; design a recovery/rejoin strategy that respects the existing token and lease, and test save failures and BindToClose under budget before rollout. Never change store identity. **Dependencies:** DataService, session lease, test harness/Studio API test. **Risk:** high; needs careful handling to avoid concurrent writers. No emergency patch was applied because a one-line retention change alone does not preserve memory after server termination.

# P1 Issues

**BR-002 · P1 · Inventory/menu ownership.** Files: `src/StarterPlayer/StarterPlayerScripts/Controllers/BloomUI.luau`, `src/StarterPlayer/StarterPlayerScripts/Controllers/InventoryV2Controller.luau`, `src/StarterGui/BloomUI.model.json`, `tools/bloom-ui-editor/app.js`. **Observed:** SeedSatchel's RenderMenu branch directly calls InventoryV2.Render and clones InventoryPrototype; editor treats `seedbag` and `inventory_v2` as different scenes. **Root cause:** prototype was wired as the live menu without a separate runtime route/feature decision. **Impact:** SeedSatchel behavior/preview contract diverges from authored intent, potentially leaving its authored template unused. **Fix:** establish explicit menu ownership after checking actual model node tree; keep prototype isolated from SeedSatchel until intentionally released and bind the intended SeedSatchel implementation to its own route. Preserve server inventory semantics. **Dependencies:** GUI model verification, menu flow test. **Risk:** medium.

**BR-003 · P1 · Workshop respec/progression.** Files: `src/ServerScriptService/Services/WorkshopService.luau`, `src/ServerScriptService/Services/GardenPlotService.luau`, `src/ServerScriptService/Services/StatsService.luau`. **Observed:** Respec refunds purchased nonpermanent nodes and truncates garden slots above new capacity and equipped bees above new bee capacity. Owned copies remain, but planted flower level/XP/mutation in removed slots are erased; respec can change active progression without preview. **Root cause:** capacity collapse directly replaces slot tables. **Impact:** accumulated per-slot progression lost. **Fix:** implement explicit preservation/recovery of displaced planted slot state or block respec until slots are emptied, with validated migration tests. **Dependencies:** garden capacity/plant ownership, UI warning. **Risk:** high.

**BR-004 · P1 · Season/session transaction.** Files: `src/ServerScriptService/Services/SeasonService.luau`, `src/ServerScriptService/Services/DataService.luau`, `src/ServerScriptService/Services/PlayerService.luau`. **Observed:** SeasonConfirm sets Busy and CommitProfile; on unknown durable outcome CommitProfile marks Lost and kicks, but `Busy` is cleared afterward. PlayerRemoving can concurrently wait for transaction for 20 seconds, and BindToClose waits only 25 seconds for every release. **Root cause:** transaction, leave and shutdown have overlapping deadlines and no explicit completed transaction outcome handoff. **Impact:** critical turn outcome can be unconfirmed or leave stale session lock; potential blocked progression/rejoin. **Fix:** serialize per-player leave/transaction operations and specify bounded shutdown completion states; test uncertain UpdateAsync callback outcomes. **Dependencies:** BR-001. **Risk:** high.

# P2 Issues

**BR-005 · P2 · Snapshot performance.** Files: `src/ServerScriptService/Services/PlayerService.luau`, `src/ServerScriptService/Services/RemoteService.luau`, `src/ServerScriptService/Services/UIStateService.luau`, `src/StarterPlayer/StarterPlayerScripts/Controllers/BloomUI.luau`. **Observed:** full profile copy, odds rebuild, inventory/workshop/trial projection and full RenderMenu are triggered on each accepted request plus every SyncSeconds=1 per player; StateRequest can be called every .4 seconds. **Root cause:** no revision/delta path and snapshots on both periodic and action paths. **Impact:** scaling and UI rebuild pressure, rate-limit exposure. **Fix:** coalesce pushes per tick and add revision-aware snapshots or targeted updates; preserve initial handshake. **Dependencies:** state shape compatibility. **Risk:** medium.

**BR-006 · P2 · Public replication scaling.** Files: `src/ServerScriptService/Services/PlayerService.luau`, `src/StarterPlayer/StarterPlayerScripts/Controllers/PollinatorController.luau`, `src/StarterPlayer/StarterPlayerScripts/Controllers/ActivityController.luau`. **Observed:** each second, all players' bee frames and tokens are accumulated then broadcast to every player, regardless of location/settings. **Root cause:** global FireClient loop with full aggregate payload. **Impact:** O(players² × displayed entities) transmission and client processing. **Fix:** spatial/visibility filtered per-recipient batches at bounded frequency. **Dependencies:** client display settings and map positions. **Risk:** medium.

**BR-007 · P2 · Workshop GUI lifecycle.** Files: `src/StarterPlayer/StarterPlayerScripts/Controllers/BloomUI.luau`, `src/StarterGui/BloomUI.model.json`. **Observed:** full-screen focus hides HUD and captures wheel with high-priority ContextActionService; panning and zoom have explicit disconnect/restore, selection/zoom/canvas position persist in controller memory. Yet each one-second State applies RenderMenu, ClearPanel, re-clones WorkshopTemplate and rebinds all node hover/input handlers. **Root cause:** full menu reconstruction on snapshot rather than state patch. **Impact:** interruptible hover/drag, allocation churn and UI continuity issues. **Fix:** keep Workshop shell mounted while open, update node states in place and preserve input ownership. **Dependencies:** BR-005. **Risk:** medium. Hidden nodes are visually masked, but client receives WorkshopConfig with true names/effects: this is presentation concealment, not secret data protection.

**BR-008 · P2 · Roulette lifecycle race.** Files: `src/StarterPlayer/StarterPlayerScripts/Controllers/BloomUI.luau`, `src/ReplicatedStorage/Config/RollAudioConfig.luau`. **Observed:** initial viewport hidden; click toggles Auto and animation; STOP hides and late Reward returns without reveal. During landing, StopRouletteAnimation increments generation, but landing coroutine later unconditionally clears `RouletteLanding` and may act on a newly restarted Auto session; SetAutoRolling(false) is also called for any failed Roll Ack, including a late Ack from an old request. **Root cause:** rewards/acks carry no request generation and landing cleanup is not generation guarded. **Impact:** a rare start/stop/restart race can interrupt or hide the new animation. **Fix:** correlate server roll responses to client generation or keep a local request sequence and guard every landing continuation. **Dependencies:** RemoteService/RollService response contract. **Risk:** medium.

**BR-009 · P2 · Profile schema invariants.** Files: `src/ServerScriptService/Data/ProfileSchema.luau`, `src/ServerScriptService/Services/InventoryService.luau`, `src/ServerScriptService/Services/WorkshopService.luau`. **Observed:** Prepare sanitizes some fields but does not cap/validate all currencies, seed counts, Workshop points/nodes/sources, settings and flags against registries; `U.Number` handles numeric coercion while negative finite balances/counts are accepted; arbitrary unknown nested keys survive reconciliation. **Root cause:** serializability check is broader than domain validation. **Impact:** malformed stored profiles or a future buggy mutation can persist impossible state; this is not evidence of a current client arbitrary-reward exploit. **Fix:** field-level schema, bounded numbers and known keys with migration-safe preservation of legacy archive; test round trips. **Dependencies:** migration fixtures. **Risk:** high.

**BR-010 · P2 · Location/trial access flow.** Files: `src/ServerScriptService/Services/MapService.luau`, `src/ServerScriptService/Services/BuildTrialService.luau`, `src/ServerScriptService/Services/UIStateService.luau`, `src/StarterPlayer/StarterPlayerScripts/Controllers/BloomUI.luau`. **Observed:** UI map computes CanUnlock from hive level while server gate interaction additionally requires physical distance; trials require player at shrine, matching sector/unlock, and send an Open/Trials event from shrine. **Root cause:** UI affordability and actionable status are separate without a clear nearby indicator. **Impact:** available-looking controls can fail away from the gate/shrine; confusing progression. **Fix:** expose distance requirement in derived UI and guide to world prompt, preserve server checks. **Dependencies:** UI state only. **Risk:** low.

# Data Safety Findings

Store identity is unchanged from FruitRNG. Raw legacy tables are wrapped; a lease token prevents an ordinary concurrent save; invalid serializable shapes receive defaults, and Prepare intentionally retains a returning player's empty garden and seed copies before reconciliation. CommitProfile uses a transaction id and marks unknown outcomes Lost, which is stronger than normal save. BR-001, BR-003, BR-004 and BR-009 describe the remaining risks. `ProfileSchema.Prepare` may discard invalid/unowned planted slots during load or save, so its repair should be tracked as a migration with evidence, not silently attributed to client UI. No DataStore mutation was performed during this audit.

# Remote Security Findings

Meaningful Request actions: Ready, Roll, Plant, EquipBee, Dissolve, FlowerUpgrade, Flag, Activity, WorkshopBuy, Respec, Trial, SeasonConfirm, Card, Keepsake, Skip, Replay, Menu, Setting, DissolveFilter, SeasonCancel. StateRequest is separate. Global Request bucket is burst 12, refill 6/s; StateRequest limit .4 seconds; incoming action is bounded to 32 chars and string args to 100 chars, but table args are not generally shape checked at transport. Each mutation checks relevant IDs/types and authority in its owning service: Roll cooldown/eligibility/result; Plant slot/ownership/distance; EquipBee count/capacity; Dissolve free/protection/quantity; Activity offered token/index/expiry/proximity/hold; Workshop cost/parent/hive/season; Trial id/sector/shrine; Season token/expiry/revision/eligibility. `Setting` validates known keys/boolean or finite volume. `Flag` checks discovery and target collection, but does not separately check SeedSatchel unlock; this is a minor authorization inconsistency with Dissolve/Upgrade. Prompt handlers use server proximity. No observed client-provided reward, rarity, price, or arbitrary currency input reaches a mutation. Expensive request: StateRequest independently rebuilds full state up to 2.5/s; accepted no-op/invalid Request still calls Push. `Skip` intentionally advances tutorial without progression cost; verify product policy, not an exploit assertion.

# UI Architecture Findings

`BloomUI.model.json` is Rojo-authored StarterGui; `tools/bloom-ui-editor/server.py` reads/writes that path, backs up dirty model before AI SYNC, stashes other changes, pulls and restores/merges model changes; `app.js` has design vs preview scenes and mock preview data. Authored static SafeRoot/HUD/roulette/MainPanel/templates are consumed by BloomUI. Runtime builds generic menu content, clones InventoryPrototype and WorkshopTemplate, creates activity visuals, and updates authored GUI properties. A wrong/missing authored node makes BindStaticUI's WaitForChild unbounded or errors after SafeRoot (10 s); the 1.2 MB model could not be independently enumerated, so exact z-index/hitbox claims are unverified. At 1366×768 the Inventory V2 canvas is 1220×660; at 1280×720 runtime caps width at 1256 and height at 696, but header/content reduce actual room. At 1920×1080 it remains 1220×660. These are code-derived dimensions, not rendered QA. BloomUI's responsive layout returns for widths ≥700; desktop overlaps depend entirely on the authored model. ModalShade and MainPanel are toggled together; WorkshopFocus hides HUD/reveal, and RewardPresentation pauses during Workshop. The editor's preview uses different scene rules, so it cannot establish actual game input/z-index behavior.

# Core Loop Findings

The implemented loop is starter bee from Hive prompt → planted Daisy pollinated → honey/coins/flower and bee mastery/Bloom charge → hive capacity and Workshop points → server roll grants seeds and bees → available flower copies plant near plot / duplicates dissolve into Petal Dust → better garden synergies/bee effects → sectors at hive thresholds, world activities and trials grant Workshop points → Workshop upgrades → season turn grants Ancient Nectar and persists selected legacy progress. Discovery, journey and tutorial events expose these stages. FieldGuide is a discovery view, not the owned inventory; Garden planting is near a physical plot. `BloomConfig` currencies have meaningful sinks (Honey/Hive, Coins/Workshop, Dust/Workshop+mastery, Nectar/Legacy branch); bee mastery is accumulated but its direct reward is not evident from the inspected service paths. A non-player-visible source of confusion is the active Inventory V2 being installed under SeedSatchel. See BR-010 for UI vs physical unlock mismatch.
