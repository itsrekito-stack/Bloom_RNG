PROMPT 0 — ЗАКРЕПИТЬ ПРАВИЛА РАБОТЫ С ПРОЕКТОМ

Ты работаешь с существующим Roblox-проектом на Luau/Rojo. Это не проект с нуля.

Главная цель rebuild:
ROLL -> FLOWER SEED / BEE -> посадка/рой -> пчёлы работают -> игрок ловит короткие активные окна -> BLOOM METER -> SPECIAL BLOOM ROLL -> HIVE / WORKSHOP -> новая зона -> SEASON TURN -> новое правило сезона.

Главные архитектурные правила:
1. Сервер всегда authoritative для RNG, выдачи наград, валют, прогрессии, Garden state, Workshop purchases, Trials, world events, Season Turn и data migration.
2. Клиент отвечает за UI, анимации, локальную рулетку, камеры, VFX, подсказки, ввод и presentation.
3. Не создавай shared Workspace roulette.
4. Не делай механический Find/Replace Fruit -> Flower. Старая Fruit domain должна быть логически удалена/мигрирована.
5. Не создавай параллельные сервисы с тем же назначением, если можно безопасно расширить существующий.
6. Не ломай DataService и reconnect.
7. Все migration должны быть idempotent.
8. Не оставляй nil references, dead requires, старые remotes и обращения к удалённым profile fields.
9. Не меняй Packages/React-Lua без прямой необходимости.
10. Все magic numbers выноси в Config.
11. Все Tweens/Connections/temporary Instances должны иметь cleanup.
12. UI должен работать на desktop и mobile.
13. Не добавляй paid RNG, скрытые odds и fake near-miss.
14. После каждого этапа проект должен запускаться в Studio.

Перед каждым изменением:
- сначала прочитай реальные файлы проекта;
- найди source of truth;
- перечисли файлы, которые будешь менять;
- если реальные имена отличаются от названий в ТЗ — используй существующие эквиваленты, а не создавай бессмысленные дубликаты.

После каждого этапа обязательно:
- перечисли изменённые/созданные/удалённые файлы;
- перечисли конкретно сделанные изменения;
- укажи риски;
- дай 5–10 конкретных Studio tests;
- не переходи к следующему этапу сам.
